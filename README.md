# ERRNO — монітор здоров'я астронавта

Навчальний прототип: корабель надсилає покази, штраф рахує індекс здоров'я, а Земля бачить їх на 20 хвилин пізніше. Це симуляція, не медична порада.

Стек: FastAPI, aiosqlite, SQLite WAL, Next.js, TanStack Query. Датчики імітує **генератор у браузері**: кругла кнопка в куті екрана відкриває вікно з готовими сценаріями, ручним керуванням датчиками і записами. Окремих скриптів чи токенів пристрою немає.

## Як це працює для відвідувача

- **Вхід без паролів.** Перший екран: «Оберіть обліковий запис». Натиснули картку — увійшли. Якщо ви вже входили, сайт одразу відкриває ваш акаунт; змінити його можна в меню налаштувань.
- **У кожного своя копія.** Браузер сам створює випадковий ідентифікатор простору (`localStorage`, ключ `errno:workspace`) і шле його у заголовку `X-Workspace`. Бекенд тримає для кожного ідентифікатора окрему SQLite-базу, тож демо різних людей не перетинаються. Неактивні простори видаляються через 3 години.
- **Генератор — вікно, а не окрема сторінка.** Запуск триває до 10 хвилин і сам зупиняється. Останні 3 запуски зберігаються в `localStorage`, їх можна відтворити, експортувати й імпортувати.
- **Все локальне.** Налаштування генератора, записи, обліковий запис і ідентифікатор простору лежать у `localStorage` вашого браузера.

## Запуск

```bash
cd backend && python -m venv .venv && .venv/bin/pip install -r requirements.txt
cd ../vita-astronaut-health-monitor/frontend && npm install && cd ../..
make demo
```

`make demo` піднімає API на `http://127.0.0.1:8000` і сайт на `http://localhost:3000`. Окремо: `make api`, `make web`. Налаштування середовища: `.env.example` (для локального запуску потрібні лише значення за замовчуванням).

Акаунти (без паролів): `astronaut` (Олена Кравець, `A1`), `officer` (Тарас Бондар, `A2` — звичайний космонавт з break-glass у критиці, не медперсонал), `doctor` (головний лікар).

Розгортання на Vercel + Railway: [docs/HOSTING.md](docs/HOSTING.md) (українською та англійською).

## Що рахує статус

Для метрики `D = |V − B|`. Якщо `D` не більший за допуск, штраф 0, інакше `k * (D − допуск)`. Сума штрафів `S`, індекс `max(0, 100 − S)`.

Статус 0, коли `S < 15` і жоден штраф не досягає 35. Статус 1, коли сума між 15 і 40. Статус 2, коли сума від 40, один штраф від 35, або три сповіщення підряд у статусі 1. Вихід зі статусу 2 — після шести оцінок нижче порога.

Сатурація і сон штрафуються лише нижче бази. Втома, доза і CO2 — лише вище. Під час `exercise` пульс, дихання і лактат мають штраф 0. `eva` штраф не гасить.

Колір зони на картці лишається підсвіткою одного числа. Рішення «кликати лікаря» береться лише зі штрафу.

Глюкоза зберігається в мг/дл. Старі ммоль/л помножені на 18 один раз у конфігурації і межах.

`PUT /limits` діє одразу. Телеметрія лікаря і `POST /actions` чекають `SIGNAL_DELAY_SEC` (типово 1200 с симульованого часу).

## Калібрування зон

`cd backend && .venv/bin/python scripts/calibrate_report.py` порівнює межу жовтої і червоної зони з порогами штрафу. Числа навмисно не підкручувались. Червона межа, де штраф менший за 35, і жовта, де сума вже від 40:

- A1, червона межа нижче 35: пульс 49.9 (15.96), дихання 9.9 (12.65), тиск 89.9 (0.36), температура 35.4 (26.40), глюкоза 54.9 (18.76) і 125.1 (34.25), калій 3.19 (14.25), натрій 129.9 і 150.1 (27.90), кальцій 8.0 (28.80) і 10.81 (29.52).
- A2, жовта межа вже дає суму від 40: дихання 24 (46), натрій 150 (45), кальцій 10.8 (43.20), ICP 20 (43).
- A2, червона межа нижче 35: пульс 49.9 (12.02), дихання 9.9 (1.15), сатурація 90 (28.80), тиск 89.9 (0), температура 35.4 і 38 (30.80), глюкоза 54.9 (23.41) і 125.1 (29.60), калій 3.19 (12.75), натрій 129.9 (9.90), кальцій 8.0 (14.40), сон 4.9 (28.60), доза 1.51 (33.31).

Разом 28 розбіжностей. Один допуск має накривати зелену смугу обох баз, тож симетрично закрити обидві червоні межі не виходить.
